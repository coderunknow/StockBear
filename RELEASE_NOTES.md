# StockBear v0.1.0-dev4 — development prerelease

StockBear is an independent C++17 UCI chess engine. Its board, legal move
generation, state management, alpha-beta search, evaluation, dead-position
analysis and UCI controller are implemented in this repository; it neither
embeds nor calls another engine to select moves. This is an early development
release, not a stable or leading-strength engine.

## What this release is, and what it is not

dev4 builds a complete neural evaluation — features, incrementally updated
accumulator, quantised network format, scalar and AVX2 kernels, self-play data
generator, trainer, quantiser and an independent verifier — and then measures it.
At 2,500 nodes per move the trained network **loses 708 Elo** (95 % CI
[−1011, −405], 60 games) to the classical evaluation of the same binary, so it is
**not** embedded and **not** the default. The five search refinements added in the
same release were each measured against the same binary with only that option
flipped: all are neutral or negative at a fixed node budget and at a fixed time
control, so all of them stay off.

**The default configuration plays exactly as dev3 does.** The depth-6 and
depth-7 benchmark signatures are unchanged (`e06c4352681ae8eb`,
`5bceff035f2a4ae4`), and a paired match against the released dev3 binary at a
fixed node budget reproduced the same-binary null control game for game. This
release therefore claims **no strength gain**; it claims verified infrastructure
and honest negative results.

## What is new

- **Neural evaluation infrastructure**, written for this project: 768 piece-square
  features per perspective, `768 → 128 → 32 → 1` with clipped ReLUs, an
  accumulator maintained incrementally through `make_move`/`unmake_move` and
  checked against a from-scratch rebuild by `verify_state()`, a versioned
  little-endian file format with full validation, and two kernels (portable scalar
  and AVX2 behind a runtime CPUID check) that are tested for bit-identical output.
- **UCI options `NNUE` (check, default false) and `NnueFile` (string).** The
  release binary embeds no network; `NNUE true` reports why it cannot be honoured
  instead of pretending. Loading a network from a file works and is covered by
  tests. The measured network is committed under `benchmarks/training/` so the
  experiment can be reproduced, with a prominent warning that it is much weaker
  than the classical evaluation.
- **Training pipeline.** `stockbear selfplay` (seeded, reproducible),
  `scripts/nnue_features.py`, `train_nnue.py` (game-level split, best-validation
  checkpoint, corpus hashes stored in the checkpoint), `convert_nnue.py`
  (percentile calibration, rounded shifts), `verify_nnue.py` (an independent
  integer re-implementation; 0 differences on 2,000 positions) and
  `embed_nnue.py`.
- **Five switchable search refinements** — `ModernLMR`, `MoveCountPruning`,
  `IIR`, `Improving`, `TTEval` — all off by default, all measured. `razoring` is
  documented as not implemented and is not advertised.
- **A match harness that can resolve small effects.** Fixed-node play is
  deterministic, so colour-reversed pairs scored identically and the pentanomial
  had zero variance: a match could not tell a +100 Elo change from a −100 Elo one.
  `scripts/tournament.py` gained a seeded per-move node jitter, and the repository
  gained a 240-opening random suite (`benchmarks/positions/openings_dev4.txt`,
  generated by `scripts/make_openings.py`) plus `scripts/experiment_table.py` to
  rebuild the results table from the raw records.

## Verification

- CTest: **11/11** entries pass in a Release build (4.8 s), including the new
  `nnue` entry (7 tests) and the new `nnue_features` differential entry.
- `unit` group: **39** tests. (The dev3 notes said 37; the source at that tag has
  39, and the miscount is corrected here rather than carried forward.)
- Bench signatures: defaults unchanged from dev3; each dev4 switch alone changes
  the signature except `TTEval`, which is a verified no-op on this search.
- Tactics suite: 25/25 at 60,000 nodes. Endgame suite: 24/24 at 400,000 nodes,
  16/24 at 20,000 nodes — both measured on this binary, not inherited from dev3.
- CI: Linux Debug/Release, ASan+UBSan, ThreadSanitizer, Clang, minimum CMake 3.16
  and Windows Debug/Release jobs run for the release commit. Check the CI run for
  the exact commit — this document does not substitute for it. The Windows binary
  is built and tested by CI; it was not executed by hand on a Windows machine.

## Compatibility

Standard UCI: `uci`, `isready`, `ucinewgame`, `position`, `go`
(depth/nodes/movetime/clocks/increments/movestogo/infinite/searchmoves), `stop`,
`quit`, `debug`, and `info` lines with depth, seldepth, multipv, score, nodes, nps,
hashfull, time and pv. Options: `Hash`, `MultiPV`, `EvalParams`, `NNUE`,
`NnueFile` and the boolean search switches. No `Threads` option: the search is
single-threaded and advertising it would be a claim the binary cannot honour.
Ponder, Chess960, an opening book and tablebases are not implemented.

No command or option was removed or changed in meaning in this release.
