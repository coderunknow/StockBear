# Training data and model provenance (dev4)

Everything in this directory describes how the shipped neural network (if one is
shipped) was produced. The corpora themselves are **not** committed: they are
hundreds of megabytes of generated positions. What is committed is enough to
regenerate them and to verify that a recorded run used the data it claims.

## 1. Self-play corpora

Generated by `stockbear selfplay`, the engine's own generator, which plays games
with a randomised opening and writes one line per searched position:

```
<result> <game-id> <fen>
```

`result` is from the point of view of the side to move at that position
(`1` = the side to move won, `0.5` = draw, `0` = the side to move lost). The game
id is what the train/validation split is based on, so positions from one game can
never straddle the split.

| Corpus | Games requested | Positions | Games in file | SHA-256 | Size |
| --- | --- | --- | --- | --- | --- |
| `corpus-a.txt` | 12000 @ 4000 nodes | 1,359,955 | 11,076 | `6096aaf22b31569d357a640f70827c6c6c986e68d7601c5e2ef4ce6eb86c0b3d` | 82.1 MB |
| `corpus-b.txt` | 12000 @ 4000 nodes | 1,355,075 | 11,089 | `de4cc93c4308c499f6497268ee311628a89f3e5ab23ba37ce8b96d45896bfd48` | 81.9 MB |
| `corpus-c.txt` | 9000 @ 5000 nodes | 357,815 | 2,837 | `898cc9ff20cfb160005b6017281ca2fa8c983b1761ecf392e4f00313a94cf7c3` | 21.4 MB |
| **total** | | **3,072,845** | **24,942** | | 185 MB |

Both generation runs were stopped before reaching the requested game count (the
CPU budget for this project is one physical core); the counts above are the
actual contents of the files that were used, verified by re-hashing them after
generation stopped. `corpus-a`/`corpus-b` use seeds 101 and 202, `corpus-c` uses
seed 2026.

Commands (the binary is the dev4 build with no network embedded, i.e. the
classical evaluation, and the five dev4 search options left at their defaults so
that the data describes the shipped search):

```
stockbear selfplay --games 12000 --nodes 4000 --seed 101 --hash 16 --out corpus-a.txt
stockbear selfplay --games 12000 --nodes 4000 --seed 202 --hash 16 --out corpus-b.txt
stockbear selfplay --games  9000 --nodes 5000 --seed 2026 --hash 16 --out corpus-c.txt
```

## 2. Prepared dataset

`scripts/train_nnue.py --prepare-only` parses the corpora into
`boards.npy` (uint8 `[N, 64]`, 0 = empty, `kind + 1` otherwise), `side.npy`,
`result.npy`, `game.npy` and `split.npy`, and records the input hashes in
`manifest.json`. Splitting is a deterministic function of the game id
(`(game * 2654435761) mod 100`: `<12` train, `12..94` train, `>=95` test, with
`5..11` validation), so the split is stable when a corpus is extended by a later
generation run.

```
positions            3,072,845
games                   24,942
train / val / test   2,706,666 / 212,708 / 153,471
duplicate positions     669,141  (21.8%)
```

Duplicate *positions* are kept: they are a consequence of transpositions across
different games, and dropping them would bias the sample towards unusual
positions. Because the split is by game, a position that occurs in both a train
and a validation game is a genuine (small) leak; it is documented rather than
hidden.

## 3. Training run

```
python3 scripts/train_nnue.py \
  --input corpus-a.txt --input corpus-b.txt --input corpus-c.txt \
  --workdir nnue-work --out nnue-run/run \
  --l1 128 --l2 32 --batch 8192 --epochs 11 --lr 3e-4 --seed 20261101
```

Measured hyper-parameters and results are in
`docs/DEV4_TRAINING.md`; the exact numbers that a reproduction needs (l1, l2,
features, output scale, hyper-parameters, corpus manifest and the full
per-epoch history) are stored inside the checkpoint itself.

## 4. The dev4 network (recorded, not shipped)

| Item | Value |
| --- | --- |
| Checkpoint | `<run>.best.pt` (best validation epoch — epoch 10 of 11) |
| Serialised network | `benchmarks/training/dev4-l1-128-l2-32.nnue`, 213,720 bytes |
| SHA-256 | `ba0bc040ebe1ec36baa564ac1c08ba9bb89a3e3b3163934d873f686bf395460d` |
| Format | `SBNN` version 1, little-endian (see `docs/DEV4_ARCHITECTURE.md`) |
| Identity | `SBNN-1x128x32 <checksum>`, printed by `stockbear nnue --info` |
| Scales | `q1 = 4096`, `q2 = 16384`, `out_gain = 4800`, `actShift 5`, `h2Shift 14`, `outShift 11` |
| Validation MSE | 0.1470 (constant predictor: 0.2071) |

**This network is not embedded in the release binary and is not the default
evaluation.** It was measured against the classical evaluation of the same binary
and lost 708 Elo (95 % CI [−1011, −405], 60 games at 2,500 nodes per move); see
`docs/DEV4_TRAINING.md` §6. The file is committed so the experiment can be
reproduced exactly:

```sh
build/stockbear nnue --info --net benchmarks/training/dev4-l1-128-l2-32.nnue
python3 scripts/verify_nnue.py --net benchmarks/training/dev4-l1-128-l2-32.nnue \
    --engine build/stockbear --positions positions.txt
# or play with it:
#   setoption name NnueFile value benchmarks/training/dev4-l1-128-l2-32.nnue
```

The training *data* is not committed (185 MB of generated positions); its hashes
and generation commands are above. The checkpoint is not committed either — it is
reproducible from the corpora, the recorded hyper-parameters and the seed — but
the quantised network is, because it is the artifact every measurement in the
report refers to.
