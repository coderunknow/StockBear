# exp-0031 / exp-0032 — external rating ladder (M0.2), pre-registered

**Committed BEFORE any ladder result is collected.** Completes the unfinished
external-rating-ladder deliverable using a reproducible opponent pool built
from official source archives on the allowed hosts. This is a MEASUREMENT /
rating experiment, not a strength claim and not a dev6 gate test. No dev6 gate
is weakened or redefined here (`docs/DEV6_PREREG.md` §8 remains authoritative).

## 0. Why fixed-node, and what is measured

exp-0030 E4 showed the shared local 2-vCPU sandbox has fixed-time clock noise
(5 TIME_FORFEIT events in 400 games, −22.6 [−47.4,+2.0] Elo). A rating ladder
must be reproducible, so exp-0031/0032 use a **FIXED-NODE** control:
`--nodes 6000 --nodes-jitter 0.15`, hash 16 MB, threads 1, `--max-plies 240`,
paired colour-reversed openings. Fixed node budgets are deterministic w.r.t.
CPU clock contention (no time forfeits) and identical for every pairing. The
jitter is seeded from the game index (harness), breaking fixed-node
paired-game degeneracy while remaining reproducible from `--seed`.

This is explicitly a **pool-specific internal fixed-node rating**, NOT a 40+4
fixed-time Elo, NOT a CCRL/CEGT/FIDE-comparable rating. The dev6 strength gate
remains a separate fixed-time, isolated-runner experiment. Published ratings
and Stockfish's own `UCI_Elo` anchor are CONTEXT ONLY (see
`docs/DEV6_EXTERNAL_OPPONENTS.md`).

## 2. exp-0031 — pilot to identify informative anchors

- **Subject**: dev5 OFFICIAL artifact at champion options.
- **Anchors tested** (10): SF11 `Skill Level` 0, 4, 8, 12, 16, 20 (6);
  SF8 / SF9 / SF10 full strength (3); dev4 binary (1, known weak reference).
  `UCI_LimitStrength` is left at its default `false` so integer `Skill Level`
  is applied directly (deterministic level, though SF's `pick_best` uses a
  time-seeded PRNG — documented).
- **Games**: 40 paired games (20 pairs) per anchor = 400 games; one fresh,
  unused opening slice per anchor, all disjoint from every earlier suite;
  distinct seed per anchor (2026110701..0710).
- **Configuration smoke test**: a 4-game run to validate `Skill Level` option
  parsing and `go nodes` handling; its results are DISCARDED and excluded from
  all statistics (stored under `benchmarks/exp-runs/exp0031-smoke/`).
- **Primary metric**: fractional score + two-sided opening-clustered CR1 95%
  CI per anchor (also W/D/L, pentanomial, terminations).
- **Pre-registered "informative" criterion** (frozen): an anchor is informative
  iff the subject's score against it lies in **[0.20, 0.80]**. Outside that
  band it is SATURATED and receives no decisive allocation. No anchor is
  selected by eyeballing a favourable result.
- **Decision**: choose the anchors whose scores best bracket 0.50 (at least 2
  informative anchors required). If FEWER than 2 informative anchors exist,
  EXPAND the pool (more SF11 skill levels / SF versions' skill levels) under a
  new sub-ID and repeat the pilot — the ladder is NOT declared impossible.

## 3. exp-0032 — decisive ladder and reproducible rating estimation

- **Design**: connected bipartite (star) round-robin. Every SUBJECT plays every
  selected ANCHOR on fresh, disjoint opening slices. Subjects: dev4, dev5
  official, dev5 rebuilt, dev6 candidate (`params_abc`), dev6 failed
  (`params_dev6_a`), plus SF8/SF9/SF10 as strong external opponents. Anchors:
  the informative SF11 skill levels from exp-0031 (>=2) plus one deliberately
  saturated strong anchor to verify saturation handling.
- **Games**: >= 80 paired games per subject x anchor pairing, distinct seeds,
  fresh disjoint opening slices; target >= ~1600 games total. Power: with
  >= 80 pairs per cell a score CI is roughly +/- 10-12 Elo-equivalent, adequate
  for a bracket; the BTD fit pools all cells.
- **Opening diversity / clustering**: 8-ply openings from
  `scripts/exp_confirmation_openings.py`, deduplicated final positions, no
  overlap with any earlier suite or between cells; cluster-aware CR1 used for
  all per-pairing intervals.
- **Rating model**: **Bradley-Terry-Davidson** (draw-aware; explicit draw
  parameter) fitted by maximum likelihood on game-level W/D/L with an
  identifiability constraint (mean rating 0). `scripts/fit_ladder.py` reports:
  rating + 95% CI per engine (opening-cluster bootstrap, >= 1000 replicates),
  games per pairing, opponent-specific score and Elo difference, rating-pool
  coverage, model fit / residuals, and leave-one-opponent-out sensitivity.
- **Calibration / interpretation**: ratings are pool-specific and internal.
  SF11's `UCI_Elo` mapping (`E = 1346.6 + 143.4·level^0.806`) is reported as
  an approximate contextual anchor ONLY. The numeric gap to a "3,000 Elo"
  target is reported as **NOT CALIBRATED** unless a defensible cross-pool
  calibration with uncertainty is established; no absolute Elo is claimed.
- **Adversarial-event rules**: identical to `docs/DEV6_PREREG.md` §4
  (TIME_FORFEIT / ILLEGAL_MOVE / CRASH / UCI failure / MAX_PLY recorded, never
  hidden; engine-caused failures are losses; unadjudicated excluded and
  counted; sensitivity reported). With fixed nodes, time forfeits should be 0.
- **Decision criteria (frozen)**: the ladder is COMPLETE iff (a) >= 2
  informative anchors with non-saturated decisive cells, (b) the pairing graph
  is connected, (c) BTD fit converges with finite CIs, (d) leave-one-out
  sensitivity does not overturn the ordering, (e) all raw records/manifests
  committed. Otherwise expand the pool and repeat under a new sub-ID.
