# exp-0033 — isolated razoring ablation (SEARCH-EFFICIENCY SCREEN)

**Frozen BEFORE implementation and BEFORE any result.** This is a single,
isolated research direction after M0.1 (build integrity, exp-0030) and M0.2
(external ladder, exp-0031/0032). It is a **screen**, not a dev6 strength gate
test. `docs/DEV6_PREREG.md` §8 remains authoritative and is unchanged.

## 1. Evidence / weakness / opportunity
`src/search/search.hpp` declares `SearchParams::razoring` ("drop into quiescence
near the alpha bound", default `false`) but `src/search/search.cpp` never reads
it and `src/uci/uci.cpp` never exposes it. So the technique is genuinely
unmeasured here — not a repeat of the recorded dead ends (six extended eval
features, small CPU NNUE, cp distillation, FullSoftBudget, qsearch-lite, PGO/TT
packing/THP, incremental eval, disabling dev4 switches, best-of-N parameter
selection). At shallow depth a node whose static evaluation is far below alpha
almost always fails low; the engine currently spends a full move-generation +
recursive loop proving it. Quiescence is cheap here (no TT probe, SEE-pruned
captures only), so a null-window qsearch can confirm the fail-low for far fewer
nodes.

## 2. Mechanism (isolated, switchable, default-off)
At `depth <= 3`, non-PV, not in check, no mate window, when
`staticEval + RazorMargin[depth] < alpha` with the **fixed, pre-registered**
schedule `RazorMargin = {0, 125, 175, 300}` cp (NOT tuned on any test set), run
`quiescence(pos, alpha-1, alpha, ply)`; if its value `< alpha`, return it.
Otherwise continue normally. Guarded so it can never alter a proven mate score.
`Razoring` becomes a UCI `check` option, default `false`, so the default build
is bit-identical to dev5 and the ablation can be run on **one binary with one
switch** — no rebuild/toolchain confound at all (the confound that invalidated
the historical +33 Elo control).

## 3. Predictions (measurable, falsifiable)
- **P1 (efficiency):** `bench --depth 12` with `Razoring=true` visits strictly
  fewer nodes than `Razoring=false`; default-off signatures stay
  `243f9a1c1ba5b36` (d4) and `a14ab62224f837e5` (d16).
- **P2 (correctness):** CTest 11/11, python-chess movegen oracle 600/43,200/0,
  `evaldata --check` 600/0, UCI/perft unchanged; zero illegal moves, UCI
  failures, crashes or TIME_FORFEIT events under the fixed-node control.
- **P3 (strength screen):** fixed-node score of Razoring ON vs OFF >= 0.50 with a
  two-sided opening-clustered 95% CI reported; decision rule in §6.
- **P4 (no overclaim):** NO fixed-time Elo claim is made locally. exp-0030 E4
  showed `−22.6 [−47.4,+2.0]` with 5 TIME_FORFEIT events on this shared 2-vCPU
  sandbox; decisive fixed-time confirmation requires isolated CI runners.

## 4. Control / baseline / identities
- Candidate + control = the **same rebuilt dev6 source binary** (SHA recorded),
  built with the exp-0030 pinned toolchain (GCC 12.2.0, `-mpopcnt -mbmi2
  -mlzcnt -DSB_SEE_CACHE=1 -flto=4`, no `-march=native`, CMake 4.4.4/Ninja,
  Release). Only `Razoring` differs; both sides use
  `EvalParams=research-data/params_abc.txt`, `TTEval=true`, `Hash=16`,
  `Threads=1`.
- Context baseline: immutable official dev5
  `391cb50e13ab99168aba0255482554ab5e59d1a34af810bf8f4d2c88e5bdb918` (Track B),
  measured separately, never relabelled as a rebuild.
- TC: **fixed-node** `--nodes 6000 --nodes-jitter 0.15`, `--max-plies 240`,
  40+4 ms clock present but not used for adjudication. Fixed-node is immune to
  the shared-clock noise documented in exp-0030.

## 5. Suite / sample size / statistics
- FRESH opening suite generated by `scripts/exp_confirmation_openings.py` with a
  new seed, excluding every existing `openings*.txt` (verified-disjoint).
  1,200 openings split into **two disjoint 600-opening batches**, colour-reversed
  pairs, 1,200 games per batch = **2,400 paired games**. Opening clusters are
  the resampling unit.
- Statistics: W/D/L, paired pentanomial, opening-clustered CR1/t two-sided 95%
  CI, cluster bootstrap (1,000 replicates), LLR labelled a normal approximation.
  Both batches reported separately and combined; no subset selection, no
  excluded games except the documented `UNADJUDICATED_MAX_PLIES` rule; point
  estimates always accompanied by uncertainty.
- A separate **node-efficiency** measurement (`bench --depth 12` CSV, 3 runs each
  setting) records nodes/NPS/bench signature.

## 6. Decision criteria (frozen)
- **ADVANCE** to a larger pre-registered confirmation only if ALL hold:
  combined point >= +10 Elo AND combined 95% LCB > −10 Elo, BOTH batches
  >= −5 Elo, P1 and P2 pass, and no unexplained binary difference.
- **REJECT / CLOSE exp-0033** otherwise; append the outcome to the Failure
  Ledger with root cause and a materially different next direction. A rejection
  is a closed individual experiment, NOT termination of the dev6 mission.
- A positive screen is **not** a gate pass: Gate 1 requires >= +75 with LCB >
  +50 on both independent datasets against dev5, Gate 4 requires the exact
  packaged artifact tested. No PR/merge/tag/release follows from exp-0033.

## 7. Integrity
Raw PGN/JSONL/CSV + `cell.json` per match under `benchmarks/exp-runs/exp0033-*`,
machine-readable `benchmarks/dev6-baseline/exp0033_results.json`, build/binary
SHAs pinned. No test-set reuse as independent validation. No gate is weakened,
no negative batch is hidden, no absolute Elo or gap-to-3000 is claimed.
