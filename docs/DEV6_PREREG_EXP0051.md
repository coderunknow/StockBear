## §1 What this is, and what it is NOT

**This is the first strength measurement of an existing, already-fitted artefact.**
It is **NOT** a refit, **NOT** a rescore, **NOT** a reopening of exp-0049, and
**NOT** a relaxation of any exp-0049 threshold.

- The tested table is `benchmarks/dev6-baseline/exp0049_results/exp0049.sbpst`,
  SHA-256 **`6e31a01a6988fd2192259a101a1e089320e9ddeb8d414acf4ed3d05740d6c733`**,
  byte-identical to the file committed with the exp-0049 verdict. It is **read
  only**. No fitting code is run. No entry is edited. No cap is changed.
- **exp-0049's CLOSED / NEGATIVE verdict STANDS unchanged.** Its corpus and
  holdout remain **BURNED** and are not read by this experiment. Nothing in this
  experiment rewrites, re-scores or reinterprets that verdict.

**Why a strength measurement is justified now.** exp-0049 §7 gated its fixed-time
screen on §5 (accuracy) **AND** §6 (NPS cost). Both instruments were subsequently
shown to be invalid:

- §5: the fixed-K accuracy gate is **passable by a pure ×0.80 rescale** of every
  champion parameter on both corpora (+3.043 %, +3.109 %), and neither it nor a
  scale-invariant replacement significantly predicts measured Elo
  (`docs/DEV6_ACCURACY_GATE_VALIDITY.md`).
- §6: the fixed-depth NPS gate false-rejected **7/12** A/A pairs on the shared
  sandbox; a PASS was as uninformative as a FAIL
  (`benchmarks/dev6-baseline/nps_gate_calibration/`).

So the table was discarded by two broken instruments and has **zero strength
games**. Its 2.4712 % "accuracy gain" carries **no** strength information in
either direction. The only way to learn whether it plays better is to play.

**Protocol boundary, stated explicitly.** The ledger says ABANDON the exp-0049
*frozen configuration as a route to Gate 1*, and forecloses refits/retunes on its
burned corpus. This experiment does none of those: it takes the artefact exactly
as frozen and asks a **new, previously unanswered question** — does it play
better at 40+4 ms? It is registered under a **new ID with its own prereg, its own
fresh openings and its own frozen decision rules**, and it cannot activate
exp-0047 or satisfy Gate 1 by itself. This route was explicitly approved by the
user after the tension was surfaced rather than resolved silently.

the frozen per-square table in place of the formulaic PST.

pairing it with `params_abc` is the correct control.

### §3.1 Instrument fix required before this run (zero games)

Two defects were found and fixed in `scripts/dev6_tier1_job.py` **before** any
exp-0051 game, because either would have manufactured a convincing fake null:

1. The package carried only `stockbear`, `params_abc.txt` and `BUILD_INFO.json`;
   a referenced PST was **not** included. Jobs now declare `assets`, which are
   copied into the package, recorded in `BUILD_INFO.assets_sha256` and covered by
   `SHA256SUMS.txt`.
2. A PstFile that cannot be read is **not fatal**: the engine prints
   `info string … could not load` and **plays on with formulaic tables**, which
   in a same-binary ablation makes A bit-identical to B and yields a clean,
   plausible **fake null** (0 forfeits, nulls including 0). The runner now asserts
   per arm that every referenced PstFile **is a declared asset** AND that the
   probe prints `PstFile loaded: <path>` with no `could not load`.

All branches were exercised on the final code with **zero games**: undeclared PST
aborts; declared-but-corrupt PST is packaged then fails the load assertion; valid
declared PST logs `LOAD VERIFIED`. **Any exp-0051 job without a `LOAD VERIFIED`
line for arm A is an INVALID MEASUREMENT**, not a result.

## §5 Validity gate (enforced, not weakened)

Stage-0 and candidate-options null CIs must both include 0, and there must be
**0 TIME_FORFEIT / 0 ILLEGAL / 0 UCI / 0 ENGINE_FAILURE in ANY of the four jobs,
else INVALID MEASUREMENT**: all Elo from that run is DISCARDED with no strength
inference. Additionally, **arm A must log `PstFile LOAD VERIFIED`** in every job
that plays the candidate (§3.1); absence invalidates that job. Exactly ONE
bounded valid retry (own frozen prereg, fresh disjoint suites, never pooled) is
pre-authorised for a technical failure; a second failure CLOSES exp-0051 AS
TECHNICALLY UNRESOLVABLE. No threshold may be weakened after results.

**No accuracy gate and no NPS gate is used.** Fixed-time games charge every
per-node cost against the candidate, which is the quantity of interest.

## §6 Frozen decision rules (registered BEFORE any game)

- **ADVANCE** to a preregistered FRESH bundle candidate (measured against the
  exact immutable dev5 baseline, never a post-hoc sum) ONLY if frozen combined
  point >= **+20** Elo AND combined two-sided opening-clustered 95 % LCB > **0**
  AND both batches >= **−5** AND both null CIs include 0 AND all validity
  conditions in §5 hold.
- **CLOSE (artefact rejected)** if combined 95 % UCB < **+10** Elo OR combined
  point <= **0**.
- **Otherwise CLOSED AS INCONCLUSIVE** by a single-run compute bound: no strength
  claim, no default change, no bundle, no retune, no confirmation, no post-hoc
  sample increase.
- **A positive result does NOT retroactively validate exp-0049's accuracy gate,
  does not reopen exp-0049, and does not license accuracy gating.** It would show
  only that this specific artefact plays better, and would further confirm that
  the accuracy gate was the wrong selection variable.
- **ADVANCE does NOT satisfy Gate 1.** Gate 1 still requires point >= +75 AND
  combined 95 % LCB > +50 on two independent preregistered fixed-time batches;
  Gate 4 still requires exact final-candidate packaged binary/source/CI linkage.
  `docs/DEV6_PREREG.md` §8 is unchanged and unweakened.
