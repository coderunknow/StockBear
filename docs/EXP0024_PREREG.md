# exp-0024 pre-registration — release-artifact gate: portable champion build + champion params vs dev4

Date: 2026-11-03. Branch `arena/daa69a3b-stockbear`. This document and the
opening suite are committed BEFORE the runs they describe; the trigger push
is the run start.

## Why this experiment exists

exp-0023 measured the decisive gate (+66.4 Elo) on a runner build with
`-march=native -flto=4`. A binary compiled with `-march=native` for a specific
GitHub runner CPU must not be shipped as universally compatible. The release
artifacts (`.github/workflows/release.yml`) are therefore built with the
PORTABLE subset of the champion flags; exp-0024 measures exactly that
artifact configuration against the same immutable dev4 baseline, so the
strength claim attached to the shipped binary has its own evidence. The
runner-native +66.4 remains reported separately as the native-build
measurement of the same source.

## Candidate under test (the release artifact configuration)
- Source: this branch HEAD at push (engine source identical to the exp-0023
  candidate 737c6f4 — verified: `git diff 737c6f4..HEAD -- src/` is empty).
- Build: `cmake -DCMAKE_BUILD_TYPE=Release
  -DCMAKE_CXX_FLAGS="-mpopcnt -mbmi2 -mlzcnt -DSB_SEE_CACHE=1 -flto=4"`
  — identical to the exp-0023 champion flags except NO `-march=native`.
  Requires x86-64-v3 (POPCNT, BMI2, LZCNT: Intel Haswell 2013+ / AMD
  Excavator 2015+); documented in the release notes. The runner script
  asserts bench `243f9a1c1ba5b36f` and bench --depth 16
  `a14ab62224f837e5` at runtime, so the candidate is bit-exact in search
  behaviour to the audited candidate.
- UCI options: `EvalParams=research-data/params_abc.txt`
  (sha256 `8a9dc81fa5921e5b642c790ffa3cf84c2ba68f2193023c19dc7f3f7cea86d0be`)
  + `TTEval=true` — the champion runtime config, identical to exp-0023.
  All other options at defaults.

- 40+4 ms fixed time per move, hash 16 MB each, threads 1 each, max-plies
  240, paired openings with reversed colours.
- Opening suite: `benchmarks/positions/openings_exp0002_confirmation.txt`,
  sha256 `90e99b37daae8c1c5e12cd1a1b54743e8ee8aac20b52f78b38d20bbb4d7342de`,
  2200 paired openings, seed 2026110502, generated by
  `scripts/exp_confirmation_openings.py`, committed BEFORE this batch;
  excludes every position of all earlier suites (including exp0001).
  Previously untouched by any engine run.
- 6600 games = 12 shards x 550, seeds 2026110701..2026110712, pooled and
  CR1-clustered over openings (same statistics as exp-0023: clustered
  two-sided 95 % CI with Student-t on G-1 df, paired pentanomial, SPRT(0,5)).
- Null: 1100 games candidate-vs-candidate (same binary, same options), seed
  2026110799, same suite.
- Hardware: GitHub-hosted `ubuntu-latest` dedicated VMs (public repo, no
  billing), one runner per job, both engines on the same runner.
- Forfeit policy identical to exp-0023 (symmetric; TIME_FORFEIT = loss;
  unadjudicated games counted and reported, never silently dropped).
- GATE: clustered LCB95 strictly > +50 on the pooled 6600 games. +50 exactly
  fails. The release strength claim uses THIS number for the shipped
  artifact; exp-0023's +66.4 is the native-build figure for the same source.
- No peeking: candidate frozen; any src/ change starts a new experiment with
